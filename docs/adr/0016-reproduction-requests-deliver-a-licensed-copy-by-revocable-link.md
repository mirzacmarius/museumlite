# Reproduction requests deliver a Licensed copy by a revocable link

A Reproduction request records who asks to use one image of an Object, for what purpose, the rights evidence, the decision and what was delivered. Its requester is a Party linked to the request in the `requester` role, like the Parties of other procedures, with the name and delivery address recorded at intake. Evidence entries are kept when retracted. An approval needs at least one current evidence entry, a ready Licensed copy and the latest version of the Terms of use, and ends at a stated expiry of at most ten years, the end of a calendar day in UTC. The decision keeps the evidence it relied on, a copy of the image's recorded rights and the terms text, so later edits to the image, the evidence or the terms never change what was granted.

The requester only ever receives a Licensed copy: a JPEG made for the request from the image's verified current file (the ownership check of ADR 0001), no larger than the chosen edge, without the original's metadata, and owned in storage by the request. It is not a public rendition and does not make anything public: public display and a requester's licensed use are different rights decisions. A missing or unverified source refuses the copy instead of falling back to the original.

The copy is emailed as a link and streamed by `GET /v1/licensed-derivatives/{token}`, never as a storage URL or an attachment, so revocation and expiry stop downloads at once. Each attempt series of a delivery mints one 32-byte token; only its SHA-256 hash is kept, except that the token itself stays on the delivery while that series may still resend it, because the provider deduplicates resends with the same idempotency key only when the email is identical. Every request for a known link is a use record (served, or refused as expired, revoked or unavailable); unknown links answer 404 and record nothing. A downloaded file cannot be recalled, which the revocation dialog says.

Delivery follows ADR 0004's ledger and the email channel of ADR 0007: six attempts with backoff, idempotency key `{delivery}:{series}`, cancellation when the approval has ended or the deployment sends no email, and a staff retry that starts a new series with a new link (links already sent keep working until the approval ends). Unlike webhook and notification logs, these deliveries and attempts are not purged after 30 days: with the downloads they are the institution's evidence of what a licensee received. The approver is notified (`reproduction_delivery_failed`, Alerts) when a series ends without delivery, deciders when a request arrives (`reproduction_request_received`, Approvals), and subscribed endpoints receive `reproduction_request.decided` and `reproduction_request.ended` without the requester's personal data.

Access reuses existing permissions, so no role migration is needed. The capability `reproduction_requests` needs the Accounts module (requesters are Parties) and `media.read` with `accounts.read` to read. Intake, evidence and copies need `media.upload`; decisions, revocation, terms and delivery need `organization.manage_settings`, the authority that already approves public images.

Considered and rejected:

- Delivering the approved public rendition, because a requester's licence is usually granted where public display is not allowed, and approving it would publish the image.
- Emailing a storage URL or attaching the file, because neither can be revoked, expires on schedule or leaves a use record, and attachments hit size limits.
- Storing only the token hash for the whole delivery, because a resend after a lost response would then send a different email under the same idempotency key, which the provider refuses.
- Free-text terms on each decision, because institutions need to know which wording each licensee accepted; versioned organization terms give that with one review step.
- New `rights.*` permissions, because they would need a production role migration and the existing manage-settings authority already decides public image use.
