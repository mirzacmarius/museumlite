# One capability matrix governs navigation, pages and commands

Access to a staff-facing area is declared once, in `packages/backend/convex/utils/capabilities.ts`, as a Capability with its Module, Entitlement, Permissions and canonical route. The sidebar, command palette and page guards read the caller's states from `capabilities.forOrganization`, and backend gates throw `ConvexError({ code: "CAPABILITY_UNAVAILABLE", reason })` instead of plain errors, so what staff see matches what commands allow and every refusal can be explained.

The first missing dimension is the reason: Module, then Entitlement, then Permission. Commands gated with `requireCapability` check membership before anything else, so non-members only ever see `permission_missing` and learn nothing about an Organization's Modules or plan; gates that predate the matrix should move to it when touched. Modules are free catalog choices and Entitlements are the paid plan (Option A in `docs/decisions/monetization-coherence.md`); where an existing gate disagreed with backend enforcement, the matrix follows the backend and pricing is unchanged. Navigation hides destinations whose Module is off or whose Role lacks access, and shows plan-gated destinations locked so their page can explain the plan.
