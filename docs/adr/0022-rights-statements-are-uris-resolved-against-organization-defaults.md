# Rights statements are URIs resolved against Organization defaults when read

MUS-865. Aggregators and portals (Europeana, DPLA, LIDO and EDM harvesters) expect each Object and each image to carry a standard rights statement they can read by machine, and museums expect to set one statement for most of their holdings instead of choosing it on every record. Until now an image held only its recorded rights (`rightsStatus`, `licenseType`, the acknowledgment and the restrictions), which decide whether the portal shows it (ADR 0017), and an Object held only a credit line.

`utils/rightsStatements.ts` lists the statements MuseumLite offers: the twelve RightsStatements.org statements, CC0, the Public Domain Mark and the six Creative Commons 4.0 licences. It is pure, so the app, the public site and imports use the same list.

- A statement is stored as its canonical URI, the form its publisher uses: `http://rightsstatements.org/vocab/<ID>/1.0/` and `https://creativecommons.org/...`. The validator accepts only these twenty URIs. Imports pass what they read through `normalizeRightsStatement`, which accepts the other scheme, a missing trailing slash, the publisher's web pages (with a language, a deed or the legal code) and short codes such as "InC-EDU" or "CC BY-SA 4.0", and refuses everything else. Other Creative Commons versions are refused, never upgraded: a 3.0 licence grants different terms from a 4.0 one.
- `collections.rightsStatement` is the rights in the work itself (LIDO's rights work set). `mediaFiles.rightsStatement` is the rights in that image or file (EDM's `edm:rights`). Both are optional.
- Each Organization sets a default for Objects and one for images in `settings.rightsDefaults`, written by `organizations.updateRightsDefaults` with the Organization settings permission. A child Organization does not inherit its parent's defaults.
- The statement in effect is the record's own, otherwise the Organization's default, otherwise none. It is worked out whenever a record is read, shown or exported, never written onto the record, so changing a default applies to every record without its own statement at once, and a transferred Object follows its new Organization's default. Exports, Dublin Core, SPECTRUM and the portal carry the statement in effect. The Settings › Data CSV and the objects import template carry only the entered one, so re-importing them never turns a default into an entered fact (as with the date made, ADR 0021). A Dublin Core import stores the first dc:rights that names a statement as the Object's own, so re-importing a Dublin Core export records the statement that was in effect, a default included, as entered.
- The statement is descriptive. The portal shows the Object's and each image's statement in effect, linked to its URI, and exports, Dublin Core and SPECTRUM carry it, but it never decides whether an image is shown: the recorded rights keep the ADR 0017 gate exactly as it was. Changing only an image's statement therefore keeps its approval and its public rendition, while a change to its recorded rights still revokes them.
- A Reproduction request's decision keeps its own copy of the image's recorded rights (ADR 0016) and does not copy the statement. A Licensed copy is granted under the Terms of use, whatever statement the image carries later.

The statement lives beside `licenseType` for now. The recorded rights are a working record (who holds them, what the museum may do, until when) that also gates the portal; the statement is what the museum tells the public. Merging them would change which images the portal shows, which needs its own decision and migration.

Considered and rejected:

- Writing the default onto every record when it is set, or when a record is created. A later change of default would have to rewrite every record without an entered statement, records created before a default was set would differ from those created after, and every write would change the Object's edit version (ADR 0008) for a value staff never entered.
- Short codes ("CC-BY-4.0") as the stored value. Every consumer outside MuseumLite reads the URI, and the code would need a mapping in each export.
- Free-text statements, or any URI. Aggregators reject statements they do not know, and the portal could not name or translate them.
- Letting the statement gate the portal. A museum would have to choose a statement for every image before its Objects showed any, which ADR 0017 removed.
