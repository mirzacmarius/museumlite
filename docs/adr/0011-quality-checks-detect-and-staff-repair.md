# Documentation quality checks detect exceptions; staff repair the records

A quality check reads every collection record in bounded, resumable pages and records what it finds as findings: duplicate identifiers, documentation a profile requires but an Object lacks, records that name a Party only in text, and references to records that no longer exist or belong to another organization. It runs on the checkpoint and page-halving driver of the projection engine (`packages/backend/convex/utils/boundedJobs.ts`), rechecks the runner's access on every page, and resumes from its last page after a failure. A check never changes a record. The finding keeps what the check found as recorded (identifiers, names as written, legacy condition and provenance text, stored references), and nothing is renumbered, merged, linked or back-filled. Findings are keyed by what they concern, so a rerun updates them instead of adding duplicates. A complete check resolves the findings it no longer detects and reopens resolved ones it detects again; a cancelled or failed check resolves nothing.

Staff decide each open finding: repair the record where it is kept, or accept the finding as an exception with a reason. Acceptance reuses review records that already exist: a duplicate identifier is accepted by recording an identifier conflict review for every record that shares it, and the finding follows those reviews from then on. Any other accepted finding reopens when a later check finds something different. Repair work is assigned as case tasks with the finding as the case, so it reaches My work and the review queue with an owner, reviewer, due date and evidence links. Completing a task does not resolve the finding; the next check does.

Profiles select Objects by object type (the institution's own vocabulary) and stage: held under an Entry, in the collection, borrowed under an incoming loan, or deaccessioned. Withdrawn Objects are not checked. Documentation quality is a capability for staff who read and update collection records, on every plan, and administrators change profiles. Rejected: a separate assignment model for findings, which would split My work; and repairs made by the check, which would invent facts.
